# SAFE-Motion

Code, frozen protocols, per-segment scores, analysis outputs and round reports for the paper
*Auditing Tracking-Quality Cues in Skeleton-Based Stereotypy Detection with Matched Training Worlds* (manuscript in preparation for the IEEE Open Journal of the Computer Society). The author
list is in the paper.

The question: when a pose tracker fails more often in one class, a skeleton-based classifier
can read tracking quality instead of movement. This repository measures that with a contrast
between two training worlds. The same model is trained once with a tracking degradation tied to
the label and once with the same degradation independent of it, and both are scored under both
kinds of degradation at test time. The difference of their responses is the matched-world
interaction (MWI; earlier rounds and archived field names call it the shortcut effect, SE).
The models detect movement patterns consistent with annotated stereotypies; they do not
diagnose autism.

## Frozen-protocol discipline

Every evaluation protocol is a YAML file in `configs/protocols/`, committed before any model
was scored under it, with its pass rules and margins fixed in the same file. `REGISTRY.md`
lists the commit hash of each freeze (hashes refer to the development history, which this
release squashes), the outcome of every round, and every deviation found afterwards.
`configs/protocols/HISTORY.txt` lists every development commit that touched the protocol files,
with its local timestamp and the files it added or modified, so the order of freezes and runs can
be checked against the registry (local commit times, not third-party timestamps). Every
result from a frozen protocol is reported, including failures. No cell was rerun to move an
interval. Every reported cell has at least three seeds and a subject-clustered bootstrap interval.

|---|---|

| `results/README.md` | which results folder each paper table and figure comes from |
| `results/provenance/models.csv` | one row per final ASDPose model (218): protocol, cell, architecture, world, training assignment, seed, validity rule, loading recipe, selected epoch under both selection rules, code commit, test masks, receiving tables, checkpoint and log hashes; written by `experiments/model_provenance.py` from the registries, training logs and run lists |
| `results/<round>/REPORT.md` | one report per round, with the verdict table and readings |
| `results/pilots/` | pilot rounds v1 to v6 (development record) |
| `results/<round>/analysis/` | the analysis tables (CSV, JSON) the reports and paper tables are built from, regenerated by the release driver with the repaired model selection (v7, v9 to v13, v15conf); v16 by `analyze_v16.py`, v17 by `analyze_v17.py` |
| `results/<round>/scores/`, `registry.json` | per-segment ASDPose test scores of every planted-world and real-split model (v7 with v8, v10, v12, v13, v15conf, v16, v17; repaired selection, cleaned validation rule); `registry.json` maps each file to its world, mechanism, strength, remedy cell and seed |
| `results/<round>/scores_orig_rule/` | the files whose selected checkpoint differs under the original validation rule (13 models; 1 in v15conf, 1 in v16) |
| `results/posthoc/conf_reliance/`, `results/v16/conf_reliance/` | per-segment scores with the confidence channel permuted, for the reliance analysis |
| `results/v11/scores*`, `results/v11/dfr` | per-window score files of the transfer round |
| `results/audit_*` | natural-cue audits of MMASD and UTD-MHAD |
| `results/asdpose_id_audit/` | identity audit of the ASDPose release: decision record, per-identifier and per-group match manifests, match distances (supplement S3a) |
| `paper/tables`, `paper/figures`, `paper/claim_ledger.md` | generated tables and figures; the ledger maps every number in the abstract and contributions to its source |
| `configs/runs/` | the exact training command of every fit, one line per model (`<out_dir> <train script arguments>`), written by `experiments/make_queue_*.py` |
| `tests/` | unit tests; data-dependent tests skip when the data is absent |

Score files contain the ASDPose segment identifier, subject identifier, label, frame count, QC flag and one
model score per test condition (clean input and each planted operator, policy, strength and test
mask); ASDPose is MIT-licensed. Checkpoints, per-run training logs, feature files, the pose caches
are not included (several GB).

## Regenerating the paper tables

Score-level statistics can be recomputed from the score files in `results/<round>/scores/`, e.g.
`python experiments/analyze_v13.py` followed by `python experiments/make_tables_v13.py`.
`analyze_v16.py` and `analyze_v17.py` reproduce their `effects.csv` from the score files; the
selected-epoch and group-agreement entries of their `criteria.json` come from training logs, which
are not redistributed, and are kept in the released files.
Rescoring, the feature-based probes and the pose statistics need checkpoints, features or pose
caches, which are not included.
`experiments/build_repair_view.py --rule clean --out build/release_clean` builds a working tree
that links the code and copies the score files, and `experiments/run_release_pipeline.sh
build/release_clean` regenerates every analysis, table and figure from cleared targets; its
scoring steps need the checkpoints, which are not in this repository. Every step runs under an
output guard (`experiments/guarded_run.py`, `safe_motion/paths.py`) that refuses writes into the
archived results.

## Training

Each line of a run list in `configs/runs/` is one fit. `bash experiments/train_runs.sh
configs/runs/queue_v12.txt` trains a list in order on one GPU (protocol v9 uses
`experiments/train_v9.py` as the trainer; protocols v15conf, v16 and v17 need `SM_TRAIN_RECIPE=v15`). All fits
reported in the paper ran on one NVIDIA A10G GPU, about 7 minutes per ASDPose fit (ST-GCN about 8).

## Data

None of the datasets is redistributed here. Set the environment variables below, or place the
data under `data/` in the working directory, which is the default.

| dataset | how to obtain | variable |
|---|---|---|
| ASDPose | from its authors (Barami et al., 2024); the segment cache (`index.csv` + `keypoints.f32`) is built by the SAFE-SMM code (`stage1/build_cache.py` in that repository) | `SM_ASDPOSE_CACHE` (the cache directory) or `SM_SMM_ROOT` (a SAFE-SMM checkout with `cache/segments`) |
| MMASD | the Google Drive link on the MMASD GitHub page (Li, Bhat and Barmaki, ICMI 2023); unzip `2D_skeleton/2D_openpose.zip` in place; `ADOS_rating.xlsx` beside it | `SM_MMASD_ROOT` |
| UTD-MHAD | the official dataset page (Chen, Jafari and Kehtarnavaz, ICIP 2015); the `Skeleton/` folder of `.mat` files | `SM_UTD_ROOT` |
| SSBD/ESBD external set | built by the SAFE-SMM code from the public SSBD and ESBD videos (`external/` scripts there); the cache is not redistributed | `SM_EXTERNAL_CACHE`; `SM_STIMMING_ROOT` for the source videos and pose files used by the MediaPipe swap |

The loaders build the MMASD and UTD-MHAD caches on first use.

## Environment

Python 3.12, `pip install -r requirements.txt` (PyTorch 2.5.1; CUDA optional). Run `python -m
pytest tests/` to check the installation; tests that need a dataset skip with a message naming
the variable to set.

## Running a round

Each round is one frozen protocol, one queue of training commands, one scorer and one analysis
script. The queue files list every command.

| round | protocol | train | run list | score | analyse |
|---|---|---|---|---|---|
| pilots v1 to v6 (ASDPose, local) | `pilot_asdpose_v1` to `_v6` | `experiments/train_asdpose.py` | `experiments/run_pilot_*.sh` | `score_intervention.py`, `score_v6.py` | `analyze_v2.py` to `analyze_v6.py` |
| v7 + v8 (ASDPose, CompactCTRGCN, four mechanisms) | `pilot_asdpose_v7`, `_v8` | `train_asdpose.py` | `configs/runs/queue_v7.txt`, `configs/runs/queue_v8.txt` | `score_v7.py` | `analyze_v7.py`, `make_tables_v7.py` |
| v9 (MMASD and UTD-MHAD replication) | `replication_v9` | `train_v9.py` | `configs/runs/queue_v9.txt` (`make_queue_v9.py`) | inside `train_v9.py` | `analyze_v9.py`, `analyze_v9_variance.py`, `make_tables_v9.py` |
| v10 (quality-blind control, real-data reference, mask stability) | `identification_v10` | `train_asdpose.py --proto v10` | `configs/runs/queue_v10.txt` | `score_v10.py`, `score_v10_masks.py` | `analyze_v10.py`, `make_tables_v10.py` |
| v11 (SSBD/ESBD transfer) | `transfer_v11` | `within_set_v11.py` | none | `score_v11.py`, `build_mediapipe_external.py` | `analyze_v11.py`, `make_tables_v11.py` |
| v12 (remedies aimed at the cue) | `remedies_v12` | `train_asdpose.py` | `configs/runs/queue_v12.txt` (`make_queue_v12.py`) | `score_v12.py` | `analyze_v12.py`, `variance_v12.py`, `make_tables_v12.py` |
| v13 (arm confidence, coordinate-invariant rule) | `armconf_v13` | `train_asdpose.py` | `configs/runs/queue_v13.txt` (`make_queue_v13.py`) | `score_v13.py` | `analyze_v13.py`, `make_tables_v13.py` |
| v14 (selection repair: all 164 ASDPose fits rerun, validation alias removed from model selection) | `repair_selection_v14` | `train_asdpose.py` | `configs/runs/queue_repair_v14_headline.txt`, `_rest.txt` | `score_v7.py`, `score_v10.py`, `score_v12.py`, `score_v13.py` (repaired checkpoints) | `build_repair_view.py`, `run_release_pipeline.sh`, `make_table_repair_compare.py` |

`experiments/run_release_pipeline.sh` regenerates every analysis, table and figure that depends on
the ASDPose fits inside a tree built by `experiments/build_repair_view.py`, from cleared targets,
and stops at the first failure; `experiments/test_release_pipeline.sh` checks that it does. The
analysis steps read the score files included here; the scoring steps and the feature-based
probes need the checkpoints, which are not redistributed.
